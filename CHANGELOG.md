# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.5.0] - 2026-10-26

### Added

- **Kimi: new K3 / K2.8 Preview models** — `Kimi-K3` (flagship) and `Kimi-K2.8-Preview` join `Kimi-K2.6` in the built-in model list; both new models run under the web client's `SCENARIO_OK_COMPUTER` agent scenario with the `ok-computer` kimiplus id, while `Kimi-K2.6` keeps `SCENARIO_K2D6` and any other model falls back to `SCENARIO_CHAT` (`k2d6-chat`); matching is by lowercased model-name substring (`k3` / `k2.8` / `k28` / `k2.6` / `k2d6`), so custom model names containing these fragments also route to the matching scenario. K3 / K2.8 requests additionally carry the top-level `kimiplus_id: 'ok-computer'` and `options.model` (`k3-agent` / `k28-agent-preview`) fields (`resolveKimiChatModel` / `createKimiChatPayload` in `providerModelOptions.ts`)
- **Kimi: optional Refresh Token credential field** — accounts can store a `refresh_token` (Local Storage `refresh_token` on www.kimi.com) so expired access tokens renew automatically; provider docs and UI help text updated in English and Chinese
- **New providers: ChatGPT, Gemini, Grok**
  - ChatGPT: web-based `gpt-5` family models (`auto`, `gpt-5`, `gpt-5-1`, `gpt-5-2`, `gpt-5-3`, `gpt-5-3-mini`, `gpt-5-mini`) via Access Token, with dedicated PoW / Turnstile / browser-impersonation support (`chatgpt-pow.ts`, `chatgpt-turnstile.ts`, `chatgpt-proxy.ts`)
  - Gemini: web-based Flash / Thinking / Pro models via the StreamGenerate protocol, Cookie auth
  - Grok: `grok-4` / `grok-4-fast` / `grok-3` family models via the app-chat NDJSON protocol, Cookie auth
- **New provider: Doubao (豆包)** — ByteDance Doubao web-based models (`doubao-pro-chat`, `doubao-deep-think`) via the samantha chat completion protocol with Cookie auth; deep-think reasoning is forwarded as `reasoning_content`; single-session mode deletes the provider thread after each chat (protocol references: [dsh-doubao-plugin](https://github.com/Practice019/dsh-doubao-plugin), [doubao-2api](https://github.com/lza6/doubao-2api), [doubao2api](https://github.com/wangchuxiaoji-oss/doubao2api))
- **Built-in Chat page**: in-app chat playground with conversations sidebar (collapsible to an icon rail), streaming output, per-conversation model selection, fork and stop-generation support
- **Anthropic Messages API compatibility**: new `/v1/messages` endpoint that accepts Anthropic-format requests (tools, system prompts, thinking blocks) and translates them to OpenAI format, streaming Anthropic SSE events back (`src/main/proxy/routes/messages.ts`)
- **In-app browser login for the new providers** — ChatGPT, Gemini, Grok and Doubao now appear in the OAuth Login tab: the login window collects cookies automatically (ChatGPT captures the `authorization` Bearer token from `backend-api` requests; Gemini collects `__Secure-1PSID` / `SAPISID`; Grok collects `sso` / `sso-rw`; Doubao collects `sessionid` / `sessionid_ss`) and the collected credentials are mapped to each provider's cookie/token field
- **Doubao risk-control self-healing flow** — when a Doubao request is challenged (710022002/710022004) or hard-fails (`user invalid` / `登录已过期`), the app opens the real logged-in doubao.com page, sends a probe message through its own composer and lets the page raise its own verification UI; the user completes it there and closes the window. The app then captures the page's actual chat endpoint (`/chat/completion` with device id query), request headers, body template and full cookie jar, persists them to the account and replays them for subsequent requests — synthetic requests to the legacy `/samantha/chat/completion` endpoint get risk-flagged with 参数错误[5005]/[5014]/user invalid, while the page's own requests pass. Results are judged by the retry itself, not timers
- **Doubao request hardening** — device id and fingerprint are derived deterministically from the account id, `web_tab_id` rotates per request, PC client version fields mirror the web client, and `msToken` is only sent when known (an empty value triggers rate-limit 710022002). Response `x-ms-token` headers are captured and persisted back to the account, and closing the captcha window snapshots the whole cookie jar (updated `msToken` / `ttwid`) into the account credentials
- **Doubao conversation id capture for single-session cleanup** — the `2002` SSE event's `conversation_id` is captured during streaming and used by `POST /samantha/thread/delete` to delete the provider thread after each chat
- **Chat page conversation sidebar is collapsible** — the history sidebar can collapse to a slim icon rail (collapse/expand and new-chat buttons, 200ms width transition)
- **Chat page shows an active "deep thinking" state** — while streaming and only reasoning content has arrived, a collapsible "深度思考中…" panel with a bouncing-dots animation is shown instead of an empty spinner
- **Chat page skips `/v1/models` requests when the proxy is not running** — the model list falls back to IPC directly instead of surfacing a failed request, and the fallback failure log is downgraded to info
- **In-app OAuth login for ChatGPT starts at `https://chatgpt.com/auth/login`** instead of the bare chat URL, making the `authorization` Bearer token capture more reliable
- **Dynamic model refresh service**: providers that expose a models API are polled every 30 minutes and their `supportedModels` / `/v1/models` lists stay in sync automatically (`modelRefreshService.ts`, `modelsFetchedAt` provider field); dynamically fetched lists older than 24 hours are treated as stale on startup so the built-in list is re-applied when upstream can no longer be reached
- **Outbound API proxy**: configurable HTTP/HTTPS/SOCKS5 proxy URL for provider requests (`apiProxyUrl`), independent of the OAuth proxy mode
- **Account failover**: optional automatic retry on the next active account when a request fails (`accountFailoverRetry`)
- **Chat page wraps long content** — long code lines / URLs no longer produce a horizontal scrollbar: code blocks wrap and grow vertically, the message bubble is allowed to shrink, and the message list hides horizontal overflow

### Changed

- **Kimi Access Token help text now points to the live web token** — recommended source is the `Authorization: Bearer` value of any `/apiv2/` request in DevTools -> Network, instead of the `kimi-auth` cookie
- Project rebranded to **Chat2API Plus** (product name, repository links, updater target)
- GLM provider model list refreshed: `GLM-5.1` replaced by `GLM-5.3` and `GLM-5.3-flash` ([GLM-5.3 docs](https://docs.bigmodel.cn/cn/guide/models/text/glm-5.3))
- **Mimo credentials switched to a single full Cookie string** — instead of three split fields (`service_token` / `user_id` / `ph_token`), accounts now paste the complete `aistudio.xiaomimimo.com` cookie (help text and placeholders include the login URL https://aistudio.xiaomimimo.com); the proxy sends the whole string as the `Cookie` header and derives `xiaomichatbot_ph` from it for the chat URL query. Legacy accounts with the three split fields keep working (they are composed back into a cookie string)
- **Mimo model list refreshed from `GET /open-apis/bot/config`** — new flagship `MiMo-V2.6-Flash` / `MiMo-V2.6-Pro` / `MiMo-V2.6-Pro-UltraSpeed` plus the full legacy set (`mimo-v2.5-pro`, `mimo-v2.5`, `mimo-v2-flash`, `mimo-v2-pro`, `mimo-v2-omni`, `mimo-v2-flash-studio`, `clawm-alpha`, `clawl-alpha`, `mimo-v2.1-*`), replacing the outdated `MiMo-V2.5-Pro` / `MiMo-V2.5` / `MiMo-V2-Flash` defaults
- MiniMax model list refreshed: adds `MiniMax-M3`
- Z.ai model list refreshed (`GLM-5.3` / `GLM-5.3-flash` / `GLM-5.2` / `GLM-5-Turbo` / `GLM-5V-Turbo` / `GLM-4.7`)
- Tool calling engine and stream parser updates for the Anthropic / managed XML / managed bracket protocols
- Provider card and add-account dialogs gained new credential field types and login-guide improvements; the Add Provider dialog now renders the provider list from the built-in configuration instead of keeping a second hard-coded copy

### Fixed

- **Kimi Access Tokens renew automatically instead of failing mid-conversation** — token expiry is checked locally (JWT `exp`) before sending and during validation; expired tokens or a server-side 401 (revoked session, e.g. re-login elsewhere) trigger one renewal via the `auth.kimi.com` RefreshToken endpoint and the request is retried. Renewed credentials (access + refresh token) are persisted back to the account so restarts keep working. Validation surfaces the server's error message and gives a specific hint when no refresh token is configured. Without a refresh token configured, the proxy error message spells out both remedies: re-fetch the Access Token from DevTools (`/apiv2/` request's `Authorization: Bearer` value) or fill in the Refresh Token (Local Storage `refresh_token` on www.kimi.com) for automatic renewal. The OAuth adapter's `refreshToken()` also performs the real renewal now instead of returning null
- **Built-in providers created through the UI now include the built-in `modelMappings`** — `providers:add` (and the management API create) used to build the persisted provider without `modelMappings` / `chatPath`, so a freshly added provider forwarded display names verbatim (e.g. Mimo `MiMo-V2.6-Flash` instead of `mimo-v2.6-flash`) and upstream rejected it with "模型名称错误" until the app was restarted. Provider object construction is now centralized in `providerFactory.ts`, which fills missing fields from the built-in configuration when the id matches (regression test: `tests/providers/provider-factory.test.ts`)
- **Built-in provider definitions are re-applied on startup** — `authType` and `credentialFields` are now taken from the built-in config (legacy persisted definitions kept rendering removed fields, e.g. the old three Mimo credential fields), while `supportedModels` keep user overrides and fresh dynamic lists
- **Mimo chat switched to the current `react/chat` protocol** — the legacy `/open-apis/bot/chat` endpoint now replies with an upgrade notice ("平台升级啦，请「刷新页面」畅享更好的体验！"), verified live: chats go to `POST /open-apis/react/chat` (404 falls back to the legacy endpoint, mirroring the web client); reasoning now arrives as a dedicated `reasoningContent` SSE field (mapped straight to OpenAI `reasoning_content`, `<think>` tag parsing kept for the fallback path); v3 top-level `usage` counters (`promptTokens`/`completionTokens`/`totalTokens` + `nativeUsage` reasoning tokens) are captured for both stream and non-stream modes; upstream `error` events surface as visible content instead of being silently treated as an answer
- **Mimo cookie names aligned with the real site** — the login-state cookie is actually named `xiaomichatbot_serviceToken` (values may be double-quoted); validation, in-app login extraction and cookie composition accept both it and the legacy `serviceToken` name, and quoted cookie values are handled when deriving `xiaomichatbot_ph` for the chat URL query
- **Mimo provider aligned with the mimo2api reference** — native `<tool_call>{json}</tool_call>` blocks (including string-encoded `arguments` and calls hidden inside `<think>` blocks) are now parsed into OpenAI `tool_calls` instead of a mangled `<tool_callgt;` marker that never matched real output; thinking can actually be enabled now (a `-think`/`-thinking` model suffix turns it on and is stripped and remapped to the real upstream model id, `reasoning_effort` / the `X-Reasoning-Effort` header also enable it); upstream requests now carry a browser `User-Agent`; empty (rate-limited) upstream answers are retried once after 1.5s with a nudge appended to the query for both stream and non-stream modes, and the extra retry conversation is included in title generation and session cleanup
- **Mimo thinking output is unified across protocol versions** — v3 delivers reasoning as the dedicated `reasoningContent` field, while the v2 fallback still parses `<think>` tags; both sources are merged in non-stream responses
- **Doubao accounts are validated against the signed-in `/chat/` page** — ByteDance's passport endpoint rejects Doubao sessions (`error_code 16`), so validation now fetches `https://www.doubao.com/chat/` with the pasted cookie and checks for the embedded `"user_id_str"` (logged-out pages only carry `"user_id":0`)
- **Chat page no longer hangs in the loading state after a server error** — mid-attempt provider failures no longer terminate the client SSE stream while the provider retry loop keeps running (a late push into the ended wrapper could throw write-after-end and leave the renderer waiting); only the final failure writes the error chunk, ends the response cleanly and destroys the source stream. The Doubao per-window interaction timeout is capped at 3 minutes so unattended failures surface within ~9 minutes
- **Menus and dialogs no longer freeze the UI** — the context menu opens one frame later so it is positioned at the actual right-click point instead of jumping, open/close animations that raced with Radix's dismissal were removed, and a body guard clears a stale `pointer-events: none` left behind when a modal closes while another layer is unmounting
- Stream handling and session cleanup hardening across the GLM, Qwen AI and Z.ai adapters
- Tray and window manager stability fixes
